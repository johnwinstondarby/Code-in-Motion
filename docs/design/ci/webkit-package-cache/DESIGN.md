# WebKit package-cache experiment

Base: PR 102 head 935a90a; main remains 3304428. Johann chose package caching before the separately reviewed container fallback. No application, environment, version or release change. Existing test commands, job and install attempt limits, retries, signatures and required gates remain unchanged.

Cache only complete .deb files, via a runner-owned temporary staging folder, under an exact key including Playwright 1.63.0, the frozen tools+WebKit package list hash, runner OS/architecture and image identity. Compare that list with the installed pinned Playwright bundle; unsupported layout/platform/version fails rather than guessing. No partial key restore, indexes, locks, partial downloads or installed system files are cached.

APT source 2.7.14 pkgAcqArchive accepts an already-present archive with matching size without rehashing. Therefore blindly restoring files to APT's archive directory does not meet the requested integrity guarantee. Use the system python3-apt trusted metadata and an extra Pre-Install-Pkgs check: hash every selected file against fresh APT metadata after Playwright's unchanged apt-get update and before dpkg. Restored candidates are also checked against currently trusted metadata before admission. Bad/stale cached bytes are discarded and normal APT download is used. No local dpkg -i, arbitrary archive install, authentication override, source rewrite or key change.

The hook copies only verified, selected archive files into staging before an optional APT cleanup can remove downloaded files. An explicit cache save happens only after dependency installation succeeds and only on an exact cache miss. No cache is saved after failed installation. APT still runs on every job, including warm hits. Fresh repository package versions can require new downloads even on a matching image/list cache key; do not claim warm hits eliminate all possible package downloads.

Tests first: exact key/package agreement and workflow isolation; Python archive tests for same-size corruption, size/hash/version/trust errors, unsafe filenames and symlinks; hook-before-dpkg and successful-install-only cache save checks. Record red runs before implementing. An isolated actual APT download-only experiment checks the existing-cache assumption without installing a package. Full verify on Node 20/22, unchanged artifact evidence and three consecutive complete green WebKit jobs on the final frozen head remain mandatory. First proof job must be a genuine cold cache miss, followed by warm restores; preserve timings, effective root configuration, downloaded bytes and every retry. Stop on failure rather than keep repeating until lucky. Cache miss retains the existing two bounded dependency attempts. Part B stays held until approved merge and green main CI.

Container proposal remains outside this PR, with bounded image-pull timing and real H.264 Motion/composition decoding as explicit feasibility gates.

Primary reference: https://github.com/Debian/apt/blob/2.7.14/apt-pkg/acquire-item.cc (pkgAcqArchive constructor). Its trust chain is documented at https://manpages.debian.org/bookworm/apt/apt-secure.8.en.html .
